1. S1 (Important): TOTP verify failures never recorded in login_attempts/checked against is_locked_out — attacker with a known/leaked password can brute-force the TOTP code unthrottled. Empirically confirmed (32 consecutive wrong codes, never locked out). Fix: record failed attempts + check lockout in /login/verify.

S5: /docs, /redoc, /openapi.json publicly reachable unauthenticated, disclosing full route/schema map; /docs itself loads CDN JS (jsdelivr), violating the plan's "no CDN references" global constraint (blocked by CSP but still a real disclosure surface). Fix: docs_url=None, redoc_url=None, openapi_url=None.
3. S4: no Cache-Control header anywhere — /api/download and /view responses are edge-cacheable by Cloudflare's default extension-based caching, risking authenticated private file content served from shared cache. Fix: Cache-Control: no-store in security-headers middleware.
4. S3: python-multipart==0.0.12 (CVE-2024-53981) and resolvable starlette 0.38.6 (CVE-2024-47874) both have DoS advisories; fastapi==0.115.0 permits an unpinned vulnerable starlette range. Fix: bump fastapi>=0.115.3, python-multipart>=0.0.18, pin starlette>=0.40.0.
5. S2: unauthenticated POST /api/upload fully parses+spools the request body BEFORE FastAPI's dependency injection runs auth (framework-level ordering, not fixable via Depends) — confirmed 4MiB unauthenticated upload gets fully buffered before 401. Fix: reject on Content-Length > max_upload_bytes in the security-headers middleware, which runs pre-routing.
6. Deployment footgun (Important): Quadlet's :U,Z flags on the FILES volume would recursively chown+SELinux-relabel the user's entire real document collection on first container start, breaking their own account's read access and any other service touching that tree. Task 18 only validated :U,Z against a disposable scratch dir, masking this. Fix: use UserNS=keep-id:uid=1000,gid=1000 and drop :U on the files volume specifically (keep :U,Z on the two dedicated state volumes, which are safe to own).
7. Consistency #3 / ledger T8b+T10 combined: upload_file has no OSError/ValueError guard around its open()/write, unlike list/download/rename/move/delete — confirmed causes an unhandled 500 on both a NUL-byte filename AND an ordinary ~250-char filename (the .{name}.part temp name exceeds NAME_MAX). Fix: wrap in try/except (OSError, ValueError) -> 400, matching the pattern already used elsewhere.
8. Consistency #1: encodePath() was applied to 2 of 3 URL-construction sites in app.js — the PDF.js viewer link (line ~114) still uses raw encodeURIComponent(fullPath), same bug class fixed twice already (Task 15 for download, Task 16 for viewer.js), missed a third time. Fix: apply encodePath() there too.

Fix: add real assertions/tests for all four.
